Créer une question

Une question est un petit fichier texte, d’extension .pwq. On l’écrit avec l’aide d’une IA, ou à la main à partir d’un modèle, puis le compilateur en fait une page HTML à donner aux élèves.

1. Avec une IA

Le prompt explique le format à l’assistant (ChatGPT, Claude, Le Chat…) : il écrit alors un fichier complet et correct.

  1. Copiez le prompt, et collez-le au début d’une conversation avec votre assistant.
  2. Décrivez la question voulue : « un QCM sur la dérivée de x ↦ ax² + bx, avec des valeurs tirées au hasard », ou collez une question d’AMC à convertir.
  3. Enregistrez la réponse dans un fichier .pwq de votre dossier de questions, puis ouvrez ce dossier dans le compilateur : l’aperçu montre la question, et signale une erreur s’il y en a une.

3. Structure d’un fichier

    
Un fichier est une suite de champs. Chacun commence par trois lignes : %,
      % nom_du_champ, % ; son contenu suit. Une ligne % seule ferme le
      dernier champ.

    

      

        
ChampStatutContenu

        
          
question_titleobligatoiretitre de la question, affiché aux élèves

          
question_keywordsobligatoiremots-clés séparés par des virgules (recherche dans le compilateur)

          
question_layoutobligatoiretoujours STD

          
question_setupobligatoirecode Python : tirage des valeurs et calcul des solutions

          
question_statementobligatoireénoncé en HTML, avec formules, valeurs {{variable}} et champs de réponse

          
question_solution_explanationfacultatifexplication affichée avec la solution, écrite comme l’énoncé, sans champ de réponse

          
question_checkfacultatifcode Python de correction, pour accepter plusieurs écritures ou donner un retour ciblé

          
question_drawsfacultatifnombre de tirages préparés, de 1 à 200 (20 par défaut)

        
      

    


    
Le champ question_setup

    
    
      
  1. C’est du Python. Importez ce dont vous avez besoin (from random import randint,
        from sympy import *…). Utilisez le module random pour des données
        aléatoires.
    2. 
      
  2. Une chaîne qui contient une formule (un choix, un retour) s’écrit avec r devant les
        guillemets : r"$\frac{1}{2}$". C’est indispensable dès qu’elle contient une barre
        oblique inverse \, que Python interpréterait sinon.
    3. 
      
  3. Tous les noms sont en anglais, comme ceux de Python : choices, correct,
        answer…
    4. 
    


    
Le champ question_statement

    
    
      
  1. C’est du HTML.
    2. 
      
  2. Les formules s’écrivent en LaTeX entre $…$ (dans la ligne) ou $$…$$
        (centrées).
    3. 
      
  3. {{nom}} affiche la valeur d’une variable de question_setup : une expression SymPy
        s’affiche en LaTeX, à mettre donc dans une formule : $f(x) = {{f}}$. Dans une commande
        LaTeX, laissez des espaces autour : \frac{ {{n}} }{ {{m}} }.
    4. 
      
  4. Les champs de réponse sont des balises {% … %}, détaillées ci-dessous ; chacune
        contient sa solution.
    5. 
    


    
Le champ question_solution_explanation

    
Facultatif, il est affiché quand l’élève demande la solution. Il s’écrit exactement comme l’énoncé
      (HTML, formules, valeurs {{variable}}), sans champ de réponse :


On calcule ${{a}} \times {{b}} = {{product}}$.

    
Une explication qui demande un calcul (les étapes d’un algorithme, par exemple) se prépare en
      texte dans question_setup, puis s’affiche avec {{variable}}.


    
Le champ question_check

    
Si le champ n’est pas fourni, la réponse de l’élève est comparée à la solution, telle que l’affiche
      le bouton « Solution ». Cela convient pour un QCM, ou une saisie très simple. Mais attention :
      7/12 est faux si la solution est 14/24, 0,5 faux si c’est
      0.5. La comparaison de la réponse et de la solution est purement visuelle.

    
Le champ facultatif question_check est du Python qui étudie la saisie de chaque champ de réponse
      (une variable de même nom que le champ), et décide ok_answer['nom'] = True ou
      False ; il peut aussi définir la variable feedback, un retour qui explique
      l’erreur sans donner la réponse. Il est nécessaire pour une formule (input_math), ou
      lorsque plusieurs réponses sont justes, par exemple.


    
4. Les champs de réponse

    
Un champ s’écrit dans question_statement, à l’endroit où il doit apparaître :


{% type 'nom' paramètre=valeur paramètre=valeur … %}

    
    
      
  • 'nom' : un nom de variable Python (lettres, chiffres, _), différent des
        variables de question_setup ; dans question_check, la saisie arrive dans cette variable.
    • 
      
  • Une valeur est un nom de variable de question_setup (solution=product), un
        nombre (columns=4, tolerance=0.01), un mot parmi ceux que le champ admet
        (form=decimal) ou un texte entre apostrophes (style='width:4em').
    • 
      
  • solution= est obligatoire pour tous les champs : la variable qui contient la bonne
        réponse.
    • 
    


    

      input_value : réponse numérique

{% input_value 'answer' solution=product %}
{% input_value 'length' solution=hypotenuse tolerance=0.01 form=decimal %}

      

        
ParamètreStatutRôle

        
          
solutionobligatoirenombre Python ou SymPy (Rational(3, 2), sqrt(2)…)

          
tolerancefacultatifécart admis, par exemple 0.01 ; 0 par défaut (la valeur exacte). Obligatoire pour une solution comme sqrt(2).

          
formfacultatifécriture exigée : any (par défaut, toute écriture), integer, decimal, fraction, irreducible (fraction irréductible), scientific (1,5×10^3)

          
stylefacultatifstyle CSS du champ : 'width:5em'

        
      

      
La valeur est comparée exactement, sans Python : 1,5, 1.5 et 3/2 sont
        la même valeur. Une valeur juste dans une autre forme que celle demandée est refusée, et le retour le dit
        (« La valeur est juste, mais elle doit être écrite sous forme décimale. »). La solution affichée suit la
        forme demandée, arrondie selon la tolérance.

    


    

      input_text : réponse écrite

{% input_text 'answer' solution=noun match=loose %}

      

        
ParamètreStatutRôle

        
          
solutionobligatoirenombre, expression SymPy ou texte ; affiché comme un élève l’écrirait (19/12, x^2 + 1). Pour un nombre, préférez input_value.

          
matchfacultatifconformité exigée : normal (par défaut, les espaces ne comptent pas), exact (caractère pour caractère), loose (ni majuscules, ni accents, ni ponctuation finale : pour un mot ou un nom)

          
stylefacultatifstyle CSS du champ, le plus souvent sa largeur : 'width:4em'

        
      

      
Dans question_check, la saisie arrive comme un texte.

    


    

      input_math : formule, avec clavier mathématique

{% input_math 'derivative' solution=f_prime %}

      

        
ParamètreStatutRôle

        
          
solutionobligatoireexpression SymPy, affichée en formule

        
      

      
L’élève écrit avec un clavier mathématique (MathLive). Ce champ exige un question_check : la
        saisie y arrive en écriture texte (x^2+1), à lire avec math_expression
        puis à comparer, par exemple simplify(math_expression(derivative) - f_prime) == 0.

    


    

      input_matrix : matrice de taille fixe

{% input_matrix 'M' rows=2 cols=3 solution=product input_style='width:2.5em' %}

      

        
ParamètreStatutRôle

        
          
solutionobligatoireMatrix SymPy ou liste de lignes

          
sizel’un ou l’autrematrice carrée size × size

          
rows, colsnombre de lignes et de colonnes

          
input_stylefacultatifstyle CSS de chaque case (largeur 2em par défaut)

        
      

      
Les dimensions sont des entiers de 1 à 10, ou des variables de question_setup. Dans
        question_check, la saisie arrive comme une liste de lignes de textes ; chaque case se corrige à
        part : ok_answer["M[0][1]"] = ….

    


    

      input_vmatrix : matrice dont l’élève choisit la taille

{% input_vmatrix 'M' max_rows=5 max_cols=5 solution=product %}

      

        
ParamètreStatutRôle

        
          
solutionobligatoireMatrix SymPy ou liste de lignes ; la solution affichée prend ses dimensions

          
max_rows, max_colsfacultatiftaille maximale (10 par défaut)

          
input_stylefacultatifstyle CSS de chaque case

          
cell_width, cell_heightfacultatiftaille imposée des cases, par exemple '3em'

        
      

      
L’élève agrandit ou réduit la grille avec une poignée (ou les flèches du clavier). Sans
        question_check, une grille aux mauvaises dimensions est fausse.

    


    

      input_radio et input_checkbox : choix unique, choix multiple

{% input_radio 'answer' choices=choices solution=correct columns=4 fixed_last=1 %}
{% input_checkbox 'answers' choices=choices solution=correct scoring='b=1,m=-0.5' %}

      

        
ParamètreStatutRôle

        
          
choicesobligatoireliste de question_setup : au moins deux choix, dans votre ordre (textes avec formules, ou expressions SymPy)

          
solutionobligatoireinput_radio : le numéro du bon choix ; input_checkbox : la liste des numéros des bons choix, éventuellement vide. Les numéros commencent à 0.

          
columnsfacultatifnombre de colonnes sur grand écran, de 1 à 6 ; réservé aux choix courts. Sur téléphone, les colonnes se réduisent d’elles-mêmes. Sans lui, les choix sont empilés, tous de la largeur du plus long.

          
shufflefacultatifshuffle=0 garde vos choix dans votre ordre, quand il a un sens (« 1 », « 2 », « plus de 2 ») ; par défaut, ils sont mélangés.

          
fixed_lastfacultatifnombre de derniers choix laissés à la fin, non mélangés (0 par défaut) : pour « Aucune de ces réponses ».

          
scoringfacultatifnote indicative, dans la syntaxe d’AMC (voir « Le barème »)

        
      

      
Pour des choix qui changent avec les valeurs tirées, l’outil mcq du module
        pywims tire la bonne réponse et des erreurs types dans une réserve, sans doublon :


choices, correct = mcq(correct=a * b, wrong=[a + b, a * b + 1, a * (b - 1), (a + 1) * b], count=4)

      
Les choix sont mélangés à chaque tirage, et deux choix de même texte sont refusés. Aucun choix n’est ajouté automatiquement : pour « Aucune de
        ces réponses », écrivez-le en dernier, avec fixed_last=1. Dans question_check, la
        saisie arrive comme le numéro choisi (choix unique) ou la liste croissante des numéros cochés.

    


    

      Le barème (questions à choix)
      
Il affiche une note indicative à chaque vérification, sans rien évaluer. La syntaxe est celle
        d’AMC, et un barème d’AMC se
        recopie tel quel : scoring='b=1,m=-0.5,p=0'. Un barème n’est admis que si le champ à
        choix est le seul champ de la question.

      

        
DirectiveRôle

        
          
b, mpoints d’une bonne, d’une mauvaise réponse (par case, en choix multiple) ; 1 et 0 par défaut

          
vpoints si rien n’est coché

          
ddécalage ajouté au score

          
p, Pplancher, plafond

          
mztout ou rien : mz points si tout est juste, 0 sinon

          
haut, MAXcomme dans AMC

          
eaccepté, sans effet

        
      

    


    

      Plusieurs réponses justes : ANY
      
Dans une solution, ANY (de from pywims import ANY) marque une valeur
        quelconque : toute réponse y est juste, et le bouton « Solution » y affiche « ∗ ». Par exemple, pour
        une matrice triangulaire : Matrix(n, n, lambda i, j: 0 if i > j else ANY).

    


    
5. Compiler et publier

    
    
      
  1. Ouvrez le compilateur et choisissez votre dossier de questions (ses
        sous-dossiers sont lus aussi). Sur Chrome et Edge, il est mémorisé pour la visite suivante.
    2. 
      
  2. Cliquez sur une question pour la voir. Cochez celles à compiler, puis Compiler la sélection : une
        question donne un fichier HTML ; plusieurs, une activité (une seule page, dans
        l’ordre où vous les avez cochés, que les flèches ↑ ↓ de « Ordre des questions » changent) ou des
        pages séparées (archive ZIP).
    3. 
      
  3. Sur Moodle, ajoutez une ressource Fichier et déposez-y le fichier HTML : les élèves
        l’ouvrent dans leur navigateur, sur ordinateur ou téléphone. Vous pouvez aussi l’envoyer par
        courriel.
    4. 
    

    
Votre charte : les feuilles ont une apparence neutre. Pour les couleurs et le logo
      de votre établissement, placez un fichier brand.css à la racine de votre dossier
      de questions ; celui de l’UPEC sert d’exemple.


    
6. Bon à savoir

    

      
Pour l’entraînement, pas pour l’évaluation. La solution est toujours visible. La
        note (pour les QCM, si un barème est défini) n’est qu’une indication fournie à l’élève ; elle n’est
        transmise ni à Moodle ni à l’enseignant.

    

    
    
      
  • Une question sans champ question_check se corrige sans Python : la page reste légère. Une
        question avec question_check doit charger Python dans le navigateur de l’élève (environ
        10 Mo).
    • 
      
  • Images. Pour une figure, écrivez <img src="figure.png" alt="…"> dans
        l’énoncé, puis réunissez le .pwq et ses images dans une archive .zip, que vous
        pouvez renommer en .pwqa. Le compilateur la liste comme une question et intègre les images
        à la page, qui reste un fichier unique.
    • 
      
  • La référence complète du format est le prompt : il s’adresse à une IA,
        mais se lit aussi très bien.
